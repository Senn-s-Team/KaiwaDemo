## 交接目的与背景

本次交接记录 Codex 会话**「继续讨论产品方向 (2)」**的完整决策与开发产出。

上轮交接（[handoff-product-direction-2026-09-08.md](./handoff-product-direction-2026-09-08.md)）明确了“不做课程教学、不做虚拟人物、积累源于练习记录”的边界，但对“用户明天为何还要打开”以及入口形式留有疑问。

本轮会话中，用户与助手将焦点从虚构的长期留存机制进一步收敛到**“单次练习体验”**——确保用户即使没有提前准备话题，也能在数分钟内“容易开口、卡住能继续、结束时有明确收获”。围绕这一目标，主代理安排子代理（terra / luna）完成了三项代码改动，并通过了全量测试与构建。在会话最后，用户提出了 **`code review`** 请求，并在触发 `$handoff` 时因环境限制中断。本交接文档为下一代理提供完整的代码审查入口和后续任务建议。

## 产品决策与设计收敛

### 1. 为什么暂不推进“跨天推荐与课程”
- 用户明确表示“其实我不知道明天什么事情会让我主动再打开”。
- 强加连续性话题（如面试、求职经历追踪）或打卡机制容易脱离真实需求；在单次练习尚未带来明确价值前，设计跨天机制缺乏依据。
- **收敛结论**：把产品承诺集中到一次练习：
  - **开始前**：无选题负担，一键直达可回应的场景处境。
  - **对话中**：卡住时接住用户“当下真正想说的话”，给足支架继续沟通。
  - **结束时**：聚焦刚才的卡点，当场完成一次不看提示（或少看提示）的开口表达。

### 2. 细化到代码的三个改动点

| 模块 | 痛点 | 改进方案 | 落地文件 |
|---|---|---|---|
| **首页场景例子** | 之前点击例子只填入输入框，还要手动点“准备练习”再点“开始对话”，链路过长 | 点击例子直接触发场景生成并展示准备卡；保留准备卡让用户看清处境并点击“开始对话” | `src/components/Home.tsx` |
| **会话意图求助** | 现有“不知道怎么说”面板只根据相手上文猜提示，无法接住用户当前实际想表达的特定中文意思 | 面板增加中文意图输入；输入后针对该意图生成四级提示；新意图覆盖旧请求并丢弃迟到结果；录音时保留参考 | `src/components/ActiveSession.tsx`<br>`src/lib/api.ts`<br>`worker/scenarios.ts` |
| **完成页与重做** | 原完成页先展示大段评价和建议句，提前剧透了答案，重做入口过于靠后 | 调整展示顺序为“这次收获 → 把这一句再说顺一点（重做卡） → 查看完整复盘”；重做表达帮助等级规范为 L1 方向提示 | `src/components/SessionComplete.tsx` |

## 已完成的开发与验收细节

本次会话通过主代理监督、子代理开发的流程完成了全部三项改动，所有修改目前均保留在**本地工作树（Uncommitted）**中：

### 任务一：“怎么说”支持输入中文具体意图
- **UI 与交互**：
  - `ActiveSession.tsx` 提示面板增加可选中文意图输入框与“帮我表达”提交按钮。
  - 支持“无意图获取通用方向提示”与“有意图获取定制表达”无缝切换。
  - 录音阶段保留用户主动展开的提示内容，回合推进时自动清理。
- **请求与防竞争**：
  - `src/lib/api.ts` 与 Worker 请求支持传入 `intentionZh`。
  - Worker `buildHintPrompt` 针对用户意图生成贴合场景事实的四级梯级表达。
  - 加入竞态取消与丢弃逻辑：用户修改意图重新提交后，旧请求失效；面板关闭后的迟到网络响应不显示、不污染当前回合状态。
  - 严格保持帮助等级记录（只要查看过即计入，不因关闭或重新生成而抹消）。

### 任务二：完成页结构调整与重做聚焦
- **顺序重排**：
  - 首屏第一部分：展示本次对话的核心沟通成果与依据。
  - 首屏第二部分：直接呈现场景原题重做卡片（“把这一句再说顺一点”），鼓励当场趁热打铁。
  - 首屏第三部分：折叠展开“查看完整复盘”（听力发现、表达建议、详细分析证据）。
- **重做支架收敛**：
  - 修复原实现中提升帮助等级与界面实际只展示方向提示的不一致问题，将重做表达帮助明确为 L1 方向提示。

### 任务三：首页场景例子直达准备卡
- **链路缩短**：
  - `Home.tsx` 中点击推荐场景例子，同步更新输入框文字并直接触发 `onDraftScenario(prompt)`。
  - 自动展开准备卡，展示 `summaryZh`、双方角色与 `coreGoal`，用户确认后点击“开始对话”进入练习。

## 挂起状态与下一会话行动建议

用户在会话结束前的明确指令是 **`code review`**，但由于模型 Token / 接口问题未能在旧会话中输出。下一会话启动时，建议按以下顺序推进：

1. **第一优先级：执行 Code Review**
   - 审查当前工作树的所有改动（`git diff src/ worker/ shared/`），重点关注：
     - `ActiveSession.tsx` 中意图提交、重置与取消引用的清理边界。

     - `worker/scenarios.ts` 提示词对 `intentionZh` 的事实约束（确保模型不胡乱承诺或破坏场景设定）。
2. **第二优先级：真机/真人语音体验复测**
   - 启动本地开发服务（`npm run dev`），实际跑一个餐厅或理发场景：
     - 测试在卡住时输入中文意图，观察生成的日语是否自然易用。
     - 测试完成页直接重做时，不看答案自主开口的心理阻力是否降低。
3. **第三优先级：规范提交**
   - Review 与体验无误后，分模块或统一打包提交 Git（如：`feat: improve single session experience with intention-based hints and focused redo`）。
