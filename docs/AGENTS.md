## 权威矩阵

本目录只保留三份正文，按“产品语义 → 工程边界 → 人工证据”的依赖方向协作：

- **[product-contract.md](./product-contract.md)**：产品契约。定义用户可观察、可操作、可依赖的行为，以及产品的非承诺与验收条件；产品应该怎样工作由本文决定。它不规定模块、接口、提示词或部署实现。
- **[system-boundaries.md](./system-boundaries.md)**：系统边界。解释代码、shared Schema、配置和测试能够证明的跨系统拓扑、路由、数据所有权、存储、token、失败与部署边界；它依赖产品契约的语义范围，但不能把工程现状改写成产品承诺。
- **[user-test-template.md](./user-test-template.md)**：人工测试模板。记录人工验收、模型评价质量复核和研究流程中的观察事实、证据与决策；它依赖产品契约定义验收对象，并参照系统边界记录实现限制，不能把未观察或研究结果写成当前产品事实。

实现事实的优先级高于文档推测：当前行为以**代码、shared Schema 与测试**为准；跨系统解释由 `system-boundaries.md` 提供；人工结论由 `user-test-template.md` 记录。产品契约约束产品应有的可观察行为，但不覆盖实现事实。

## 冲突处理

正文发生冲突时，禁止静默选边。先分别核对产品契约、代码/Schema/测试及人工证据，判断冲突属于：

1. **实现缺陷**：产品契约仍是目标，代码或验证未满足它；应修正实现并补齐相应验证。
2. **产品决策变化**：产品行为有意改变；应先更新产品契约，再同步受影响的边界说明、测试记录和调用方，不能用旧文档掩盖新决策。

在未完成该判断前，不得把工程现状当作产品决定，也不得把产品意图当作已实现事实。

## 更新触发器

- **用户行为**：入口、会话、支架、恢复、复盘或其他用户可观察行为变化时，先检查 `product-contract.md`，再回查边界与人工模板。
- **工程边界**：路由、Schema、存储、token、Workflow、供应商、配置或失败边界变化时，更新 `system-boundaries.md`，并核对契约与测试记录。
- **内部重构**：模块归属、调用链或实现 seam 改变但用户行为不变时，只按代码事实检查系统边界；若跨系统职责或可观察结果变化，再同步契约与模板。
- **假想功能**：尚未实现或仅属设想的功能不得写入三份正文；先取得产品决策并落实实现，或留在任务/讨论上下文中，不创建归档文档。

历史文档由 Git 历史保留；本目录不设 archive，不重复承载旧规格、理论底稿或假想功能正文。
